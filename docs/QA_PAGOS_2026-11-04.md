## Comprobación física

Se abrió la hoja oficial Stripe desde Mis citas. Mostró MXN95.00, calculados por
el backend. Se cerró sin enviar el pago y la app mostró la cancelación.
Se introdujo después la tarjeta ficticia oficial de rechazo genérico de Stripe,
con fecha y CVC de prueba. Al enviar el intento sandbox, el SDK mostró «Tu método
de pago fue rechazado» y mantuvo el formulario disponible para reintentar.
No se utilizaron datos de una tarjeta real.
La transferencia mostró el banco ficticio, CLABE de ceros y concepto de simulación;
los botones de elegir y subir comprobante resultaron alcanzables mediante scroll.
El ciclo de subida, rechazo, reenvío y aprobación se ejecutó por API local, no mediante
el selector de archivos del teléfono.

## Hallazgos y límites

- La API QA no tenía claves Stripe. Se habilitaron solo las claves sandbox existentes
  en su configuración privada; Android y backend tienen la misma clave publicable.
- Stripe CLI rechazó el listener por falta de `stripecli_session_write` en la clave
  restringida. El propietario habilitó Debugging Tools Write y el bloqueo se
  resolvió durante la continuación descrita más abajo. No se modificaron otros
  permisos de la cuenta.
- La pantalla de transferencia mostraba «Monto» para un importe estimado sin todos
  los descuentos. Android lo identifica ahora como «Monto estimado» e indica
  confirmar el total antes de transferir. La cotización exacta de transferencia
  desde servidor es un pendiente funcional; el cambio de texto no lo resuelve.
- El éxito normal y el desafío 3DS se comprobaron posteriormente desde el celular
  (ver continuación). Permanecen pendientes la recreación de actividad durante un
  cobro y todas las combinaciones de descuentos y métodos. No se considera cerrada
  la validación completa de pagos.

Para pruebas de tarjeta se consultó la [guía oficial de Stripe](https://docs.stripe.com/testing).
Solo se permite continuar en sandbox con datos ficticios; no introducir tarjetas reales.

## Continuación: permiso del listener y pagos completos verificados

El propietario habilitó escritura en Debugging Tools para la clave restringida
sandbox. La comprobación con Stripe CLI dejó de devolver el rechazo de permisos.
Se inició un listener que reenvía únicamente eventos de éxito/fallo de PaymentIntent
a `/api/stripe/webhook` de la API QA en loopback. Su firma se configuró en el caché
privado del contenedor QA, sin modificar el entorno operativo ni versionar secretos.

Se completaron dos pagos desde la app audit instalada en el Samsung:

| Recorrido físico | Resultado del proveedor y backend |
| --- | --- |
| Tarjeta ficticia de éxito, sin desafío | PaymentSheet confirmó MXN95.00; evento de éxito, webhook HTTP 200 y un pago verificado en Mongo. |
| Tarjeta ficticia que exige 3DS | Se mostró el desafío simulado; se completó y regresó a la app. Evento de éxito, webhook HTTP 200 y otro pago verificado. |

La lectura posterior contra Mongo local confirmó exactamente dos nuevos pagos,
en dos citas distintas, con identificadores Stripe distintos y $95.00 cada uno.
Ambas citas conservaron el estado confirmada. Tras el primer cobro, Mis citas
mostró «Cita aprobada y pago resuelto. Te esperamos a la hora de tu cita».
Tras 3DS se comprobó el regreso a la app y el cierre de la pantalla de autenticación.
No se duplicaron registros en estos recorridos; esto no sustituye una prueba de
reentrega del mismo evento ni de concurrencia.

Las tarjetas, vencimientos, CVC y domicilio utilizados fueron exclusivamente datos
ficticios del sandbox. No se movió dinero real ni se utilizó una tarjeta personal.
Las capturas y referencias de operaciones permanecen en evidencia privada fuera
del repositorio. No se publicaron endpoints ni se modificó producción.

No se repitieron las suites por esta continuación, porque no cambió el código de
aplicación: se verificaron configuración efectiva, proveedor, API, base local y
recorrido físico. Permanecen pendientes la cotización exacta de transferencia,
la recuperación al recrear la actividad durante el pago y la matriz completa de
combinaciones de descuentos, puntos, propinas, depósitos y métodos.
